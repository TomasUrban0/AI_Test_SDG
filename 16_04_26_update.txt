Fase 1 — PostgreSQL (la base de todo)
Se reutiliza el PostgreSQL 13 que ya tienes para Airflow, pero creando una base de datos separada (churn_db) con 4 tablas: raw_data (snapshot del CSV original), processed_features (las 88 columnas limpias), model_metrics (historico de cada run con AUC, F1, etc.), y predictions (scores por cliente). Se modifica data_preparation.py para que escriba los datos procesados a PostgreSQL ademas de a CSV, y evaluate_model.py para que persista las metricas. El DAG se mantiene con 3 tasks, solo cambia el destino de los outputs.
Fase 2 — MLflow (experiment tracking)
Se añade un servicio mlflow-server al docker-compose que usa el mismo PostgreSQL como backend de tracking. En train_model.py se wrappea el entrenamiento con mlflow.start_run() para logear automaticamente los hiperparametros, las metricas de validacion, y el modelo como artefacto versionado. En evaluate_model.py se logean las metricas de test y se registra el modelo en el Model Registry si supera el quality gate. La UI queda en localhost:5000.
Fase 3 — Prometheus + Grafana (monitoring)
Se añaden Prometheus (:9090) y Grafana (:3000) al docker-compose, mas un Pushgateway para recibir metricas del pipeline. Se instrumenta evaluate_model.py con prometheus_client para pushear metricas custom despues de cada run: model_auc, model_f1, pipeline_duration_seconds, data_rows_processed. Grafana viene con un dashboard pre-configurado que muestra la evolucion del AUC, y una alerta si cae mas de un 5% respecto al baseline.
